# STT-Gateway 1차 작업계획서

> **작성일**: 2026-04-09
> **담당**: STT-Gateway 개발팀
> **목표**: 핵심 패키지 전체 구현 (스켈레톤 → 동작 가능한 베이스 완성)

---

## 1. 1차 작업 목표

현재 프로젝트는 `SttGatewayApplication.java` 하나만 존재하는 초기 스켈레톤 상태입니다.
1차 작업에서는 **전체 아키텍처의 골격이 되는 모든 핵심 패키지를 구현**하여,
실제 패킷 캡처 → STT 변환 → WebSocket Push 흐름이 작동하는 기반을 완성합니다.

### 작업 범위

| 항목 | 내용 |
|------|------|
| 빌드 설정 | `build.gradle` 의존성 완성, YAML 프로파일 구성 |
| DB 마이그레이션 | Flyway 마이그레이션 파일 (V1~V5) |
| Domain 레이어 | Entity(4개), Enum(3개) |
| Repository 레이어 | JPA Repository(4개) |
| Exception 레이어 | 커스텀 예외 클래스 및 전역 처리기 |
| Config 레이어 | AppProperties, AsyncConfig, WebSocketConfig, SecurityConfig |
| DTO 레이어 | API 요청/응답 DTO(4개) |
| SIP 패키지 | SIP 파싱 (SipParser, SipMessage, SipMethod) |
| RTP 패키지 | RTP 디코딩, G.711 코덱 |
| Session 패키지 | 콜 세션 생명주기 관리 |
| Audio 패키지 | WAV 파일 생성 (WavFileBuilder, AudioFileWriter) |
| Capture 패키지 | 패킷 캡처/디스패처 (PacketCaptureService, PacketDispatcher) |
| STT 레이어 | SttProvider 인터페이스, SttService, GoogleSttProvider, SttProviderFactory |
| Push 레이어 | WebSocket STOMP push (WebSocketPushService) |
| API 레이어 | REST Controller (CallController, SttConfigController, CaptureController) |
| Web 레이어 | Thymeleaf Controller (DashboardController) |

## 4. 기술적 주요 결정 사항

| 항목 | 결정 | 이유 |
|------|------|------|
| DB 마이그레이션 | Flyway | 스키마 변경 이력 추적, DDL 코드화 |
| 오디오 버퍼링 | ConcurrentLinkedQueue (메모리) | 통화 중 디스크 I/O 최소화 |
| 비동기 처리 | @Async + ThreadPoolTaskExecutor | 패킷 캡처 스레드와 STT 처리 스레드 분리 |
| STT 공급자 교체 | Strategy 패턴 + DB is_active 플래그 | 재배포 없이 공급자 교체 가능 |
| 전화번호 보안 | DTO 변환 시 마스킹 처리 | 개인정보보호법 준수 |
| 패킷 오류 처리 | catch + log.debug + 무시 | 단일 패킷 오류로 전체 캡처 중단 방지 |
