## 3. 검토 결과 — 치명적 이슈 (Blocking)

배포 전 반드시 해결해야 하는 항목입니다. 해결하지 않으면 **애플리케이션 기동 불가**합니다.

---

### 3-1. PostgreSQL 9.2.23 — 핵심 라이브러리 3개 레이어 모두 비호환

현재 설치된 PostgreSQL 9.2.23은 EOL(지원 종료) 버전으로, 사용 중인 라이브러리 전 스택과 호환되지 않습니다.

| 레이어 | 최소 요구 버전 | PostgreSQL 9.2 결과 |
|--------|-------------|---------------------|
| **Flyway 10.x** | PostgreSQL **11 이상** | 기동 즉시 에러로 종료 |
| **Hibernate 6.x** | PostgreSQL **10 이상** | 일부 DDL·쿼리 실행 불가 |
| **PostgreSQL JDBC 42.x** | PostgreSQL 8.4 이상 | 연결 자체는 가능 |

**결론:** PostgreSQL을 **14 또는 15 버전으로 업그레이드** 필요.  
(PostgreSQL 9.2는 2017년 9월 공식 EOL — 보안 패치 미제공 상태)

---

### 3-2. `flyway-database-postgresql` 의존성 누락 → **조치 완료**

Flyway 10.x부터 PostgreSQL 지원 모듈이 별도로 분리됐습니다. 해당 의존성이 없으면 Flyway가 PostgreSQL에 연결 자체를 시도하지 않아 마이그레이션이 전혀 실행되지 않습니다.

**변경 파일:** `build.gradle`

```gradle
// 변경 전
implementation 'org.flywaydb:flyway-core'

// 변경 후 (조치 완료)
implementation 'org.flywaydb:flyway-core'
implementation 'org.flywaydb:flyway-database-postgresql'   // ← 추가됨
```

## 4. 운영 서버 준비 작업 (배포 전 서버 작업)

아래 작업은 **운영 서버에서 직접 수행**해야 합니다.

---

### 4-1. PostgreSQL 15 설치 (CentOS 7)

```bash
# PGDG 공식 레포 등록
sudo yum install -y https://download.postgresql.org/pub/repos/yum/reporpms/EL-7-x86_64/pgdg-redhat-repo-latest.noarch.rpm

# CentOS 7 내장 PostgreSQL 모듈 비활성화 (충돌 방지)
sudo yum -y module disable postgresql 2>/dev/null || true

# PostgreSQL 15 설치
sudo yum install -y postgresql15-server postgresql15

# DB 초기화 및 서비스 등록
sudo /usr/pgsql-15/bin/postgresql-15-setup initdb
sudo systemctl enable --now postgresql-15
```

**DB 및 계정 생성:**

```sql
CREATE DATABASE sttgw ENCODING 'UTF8' LC_COLLATE 'ko_KR.UTF-8' LC_CTYPE 'ko_KR.UTF-8' TEMPLATE template0;
CREATE USER sttgw_user WITH PASSWORD '운영_비밀번호';
GRANT ALL PRIVILEGES ON DATABASE sttgw TO sttgw_user;
```

---

### 4-2. Temurin JDK 17 설치 (CentOS 7)

CentOS 7 기본 저장소에는 Java 17이 포함되어 있지 않습니다. Eclipse Adoptium 공식 레포를 등록해야 합니다.

```bash
# Adoptium 레포 등록
cat << 'EOF' | sudo tee /etc/yum.repos.d/adoptium.repo
[Adoptium]
name=Adoptium
baseurl=https://packages.adoptium.net/artifactory/rpm/centos/7/x86_64
enabled=1
gpgcheck=1
gpgkey=https://packages.adoptium.net/artifactory/api/security/keypair/default-gpg-key/public
EOF

# Temurin 17 설치
sudo yum install -y temurin-17-jdk

# 설치 확인
java -version
# 출력 예: openjdk version "17.x.x" ... Temurin
```

---

### 4-3. libpcap 설치 및 네트워크 권한 설정

pcap4j 라이브러리가 패킷 캡처를 위해 OS 레벨의 `libpcap` 네이티브 라이브러리를 필요로 합니다. 또한 root 권한 없이 네트워크 패킷을 캡처하려면 Java 실행파일에 Linux Capability를 부여해야 합니다.

```bash
# libpcap 설치
sudo yum install -y libpcap libpcap-devel

# 설치 확인
ldconfig -p | grep pcap
# 출력 예: libpcap.so.1 => /usr/lib64/libpcap.so.1

# Java 실행파일에 패킷 캡처 권한 부여
sudo setcap cap_net_raw,cap_net_admin=eip $(readlink -f $(which java))
```

> **주의:** `java` 경로는 Temurin 설치 후 실제 경로(`which java`)로 확인 필요.

### 4-5. 운영 설정 파일 배치 (Git 미포함 — 서버 직접 작성)

**`/APP/application.yaml`** — 비밀번호 및 민감 정보 포함:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/sttgw
    username: sttgw_user
    password: "운영_DB_비밀번호"

# Google Cloud 서비스 계정 키 경로
google:
  application:
    credentials: /APP/google-credentials.json
```

파일 권한 설정 (소유자만 읽기):

```bash
chmod 600 /APP/application.yaml
chmod 400 /APP/google-credentials.json
```

> `google-credentials.json`은 Google Cloud Console에서 발급한 서비스 계정 키 파일입니다.  
> 발급 상세 절차는 [`Google_STT_서비스계정_키발급_가이드.md`](./Google_STT_서비스계정_키발급_가이드.md)를 참고하세요.

### 4-6. systemd 서비스 파일 등록

**`/etc/systemd/system/stt-gateway.service`:**

```ini
[Unit]
Description=STT Gateway Service
After=network.target postgresql-15.service

[Service]
User=ktdsuser
Group=ktdsuser
WorkingDirectory=/APP
ExecStart=/usr/bin/java \
  -Xms512m -Xmx2g \
  -XX:+UseG1GC \
  -jar /APP/stt-gateway.jar \
  --spring.profiles.active=prod \
  --spring.config.additional-location=file:/APP/
SuccessExitStatus=143
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal

# 패킷 캡처 권한 (root 없이 eth3 미러 포트 캡처)
AmbientCapabilities=CAP_NET_RAW CAP_NET_ADMIN
CapabilityBoundingSet=CAP_NET_RAW CAP_NET_ADMIN

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable stt-gateway
```

## 5. 빌드 및 배포 절차

### 5-1. 로컬 빌드

```bash
# Windows
gradlew.bat clean build -x test

# Mac / Linux
./gradlew clean build -x test
```

빌드 성공 시 `build/libs/stt-gateway-0.0.1-SNAPSHOT.jar` 생성됩니다.

### 5-2. 운영 서버 배포

```bash
./deploy.sh
# 기본값: 211.192.89.96 / 포트 7300 / 사용자 ktdsuser
```

옵션:

```bash
./deploy.sh --skip-build          # 빌드 생략 (기존 JAR 재배포)
./deploy.sh -h 다른.서버.IP       # 서버 IP 지정
```

### 5-3. 기동 로그 확인

```bash
ssh -p 7300 ktdsuser@211.192.89.96 "journalctl -u stt-gateway -f"
```

정상 기동 확인 로그 예시:
```
Started SttGatewayApplication in X.XXX seconds
Flyway Community Edition ... has successfully applied N migrations
```
